# 调试报告｜网盘对话框"一直加载中"不会实时刷新（2026-10-05）

> 现象（用户截图）：夸克网盘弹框停在 `夸克网盘 / 加载中… / 正在获取账号信息…`，
> 内容永远不变。同时**桥侧视图树里其实已经是"已登录"**。

## 一、这不是登录问题，是"更新不上来"的问题

同一次操作的两条证据（`%APPDATA%\CatClawVideo.debug\home-debug.log`）：

| 时刻 | 证据 | 含义 |
|---|---|---|
| 08:44:55.080 | `[ui] 视图树 android.widget.ScrollView[…TextView "夸克网盘",TextView "加载中…` | 弹框第一帧 |
| 08:44:55.082 | `⬆ 856B {"message":"夸克网盘\n加载中...\n正在获取账号信息..."}` | 宿主收到并渲染 |
| 08:44:57.447 | `[ui] 视图树 …z.m[…TextView "夸克网盘",TextView "选择APP跳转或扫码登录",`**`TextView "已登录"`** | 壳已经把状态更新了 |
| 08:44:57 之后 | **没有任何 ⬆ 事件** | 更新没上行 ⇒ 宿主停在 08:44:55 那一帧 |

对照组（同一份日志）：百度、UC 的弹框**有**更新事件 ——
`08:46:50.101 ⬆ 1581B {"ev":"ui-rows","seq":4,"rows":[…扫码登录…]}`、
`08:46:58.641 ⬆ 1973B {"ev":"ui-rows","seq":5,…}`。
所以通道本身是通的，**只有夸克这条"只改文本、不产生可点行"的更新发不出去**。

## 二、根因是两层，缺一层都不成立

### 层 1：桩的 `TextView.setText()` 不标脏

`JavaBridge/src/android/widget/TextView.java:41`（改前）：

```java
public void setText(CharSequence t) { text = t == null ? "" : t; }
```

真 Android 里 `setText()` 会标脏重绘；桩只存字段。而刷新线程唯一的触发点是
`View.invalidate() → Dialog.noteInvalidate()`（`View.java:53`）。
壳更新状态走的就是 `tv.setText("已登录…")`，**一次 invalidate 都不产生** ⇒ `dirty` 永远 false。

### 层 2：刷新线程只补发二维码，文本变了什么都不发

`JavaBridge/src/android/app/Dialog.java` 的 `claw-ui-refresh` 线程（500ms×240 轮）：

```java
if (d == null || !d.dirty || d.qrSent || !UiBridge.isPending(d.seq)) continue;   // qrSent 当总闸
...
if (spec.opt("qr") instanceof JSONObject q) { …发 ui-qr… }
else if (spec.opt("qrText") instanceof String u) { …发 ui-qr(qrText)… }
// 没有 else —— 文本变化不发任何东西
```

而**宿主侧其实早就支持整树就地换新**：`SpiderUiHost.cs:75`
收到 `{"ev":"ui-rows","seq":N,"tree":…}` 且该 seq 的窗口是 `SpiderTreeDialogPage` 时调
`UpdateTree(...)`。桥只在"响应点击之后"才走 `refreshRows()`（`Dialog.java:166`），
异步 setText 这条路径没人调用它。

⇒ 结论：**桥缺一个"文本变了就重发整树"的出口**，宿主不用改。

### 3.3 `JavaBridge/src/android/app/Dialog.java` — 新增出口

```java
/**
 * 把当前整树重发一次（宿主 SpiderTreeDialogPage.UpdateTree 就地换新）。
 * 线程每 500ms 轮询，所以按序列化结果去重：文字没变就一个字节都不发。
 */
void emitTreeUpdate() {
    if (view == null || seq < 0 || !UiBridge.isPending(seq)) return;
    try {
        JSONObject tree = treeOf(view, new java.util.ArrayList<>(), new java.util.ArrayList<>(),
                new java.util.ArrayList<>(), new StringBuilder());
        if (tree == null) return;
        String s = tree.toString();
        if (s.equals(lastTreeSent)) return;
        lastTreeSent = s;
        UiBridge.emit(new JSONObject().put("ev", "ui-rows").put("seq", seq).put("tree", tree));
        System.err.println("[ui] 补发 ui-rows(tree) seq=" + seq + " " + s.length() + " 字符");
    } catch (Throwable t) { System.err.println("[ui] 补发整树失败: " + t); }
}
private volatile String lastTreeSent;
```

同时让 `refreshRows()` 记住发过的树，避免点击后紧接着重复一发：

```java
-if (tree != null) ev.put("tree", tree);
+if (tree != null) { ev.put("tree", tree); lastTreeSent = tree.toString(); }
```

### 部署时发现的两个坑（值得记住）

1. **initrd 里的 `gb.dex` 与本机重编出来的不是一套规则**：部署包内 125596B / 195 个类引用，
   `build_gb_dex.py` 产出 292148B / 352 个 —— 差的是 163 个 `android/*` 桩类（部署包把它们放在
   `ui_stub.dex`，新包两份都带）。`build_gb_dex.py` 自己的 docstring 就写着"规则与
   `mk_art_initrd.py` 必须保持两处同步"，**实际已经漂了**。注入前必须先比对类集合，
   否则会造出"同一个类两份定义"这种查不动的坑。
2. `data/dalvik-cache/x86_64/gb.dex` 是 **ELF**（预编译产物，17296B），换 `/gb.dex` 不会同步它。
   本次开机 ART 正常（pong + 预热完成），说明它按 dex 回退解释执行了 —— 但这是个待观察项。

## 六、还差一步盖章

修复已跑在你的环境上，但**"点开夸克网盘 → 文本自己从『加载中』变成账号信息"需要你点一次**确认。
判据是日志出现新行 `[ui] 补发 ui-rows(tree) seq=N …`，宿主弹框随之换新。
若那行出现而界面仍不变 ⇒ 问题在宿主 `SpiderTreeDialogPage.UpdateTree` 之后；
若没出现 ⇒ 壳压根没走到 setText，那是第三层，按这条判据继续挖。
